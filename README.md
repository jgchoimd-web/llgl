# llgl — 테라리움

이 저장소에는 앱 다섯이 있습니다. **테라리움**(`app/`, 아래), **픽셀 샌드박스**(`sandbox/`), **AI 게임 공방**(`gameforge/`), **진동 뮤직**(`vibe/`), **하늘 거북이**(`turtles/`, 잠금화면 라이브 배경화면). 각각 따로 설치됩니다.

폰 안에 유리 상자가 있습니다. 위에서 내려다본 테라리움이 화면을 끝까지 채우고, 폰의 네 모서리가 그대로 유리 벽입니다.
기울이면 구슬이 구르고 모래가 흐르고 물이 쏠리며, 톡 치고 끌고 꾹 누르고 흔들면 그 안의 것들이 소리와 진동으로 답합니다.
Kotlin + Jetpack Compose(설정 메뉴만), 픽셀 아트.

| 항목 | 값 |
|---|---|
| 패키지명 | `com.llgl.app` |
| minSdk / targetSdk / compileSdk | 24 / 36 / 37.2 |
| 언어 · UI | Kotlin · Canvas로 그리는 커스텀 `View`, 메뉴는 Compose (Material 3) |
| 빌드 | Android Gradle Plugin 9.4, Gradle 9.8 (wrapper) |

## 상자 안에 든 것

- **모래 더미**(알갱이 1천여 개)와 **물웅덩이**(방울 수백 개), **조약돌·유리구슬** 7개.
- **이끼·고사리·버섯·새싹**. 설치한 날부터 일주일에 걸쳐 60%에서 다 자라고, 하루에 하나씩 새싹이 돋습니다(최대 3).
- **공벌레** 3마리, **달팽이** 2마리(점액 자국을 남김), **딱정벌레** 1마리. 어두워지면 **반딧불이**가 찾아오고 귀뚜라미가 웁니다.

## 폰이 하는 일에 상자가 답하는 법

| 하는 일 | 일어나는 일 |
|---|---|
| 기울이기 | 중력이 화면 안에서 기울어집니다. 구슬이 굴러 벽에 "팅"(크기별 음높이) + 진동, 모래가 흘러 쌓이고(13° 안쪽이면 모양을 지킵니다), 물이 쏠립니다. 공벌레는 세게 기울이면 미끄러집니다. |
| 톡 치기 | 물결·모래 튐. 공벌레를 치면 공처럼 말려 구슬처럼 구르다가 평평해지면 펴집니다. 달팽이는 껍질로 숨고 딱정벌레는 달아납니다. |
| 끌기 | 손가락이 모래와 물을 밀어내고 생물이 도망갑니다. |
| 꾹 누르기 | 먹이 부스러기가 떨어지고 공벌레들이 모여 갉아먹습니다. |
| 흔들기 | 지진. 모든 게 튀고 식물이 흔들리고 우르릉 + 긴 진동, 공벌레는 전부 말립니다. |
| 어둡게 하기 / 밤 | 조도 센서가 어둡거나 저녁 8시~아침 6시면 상자가 어두워지고 반딧불이가 뜹니다. |
| 두 손가락으로 톡 | 메뉴: 소리, 진동, 새 테라리움. |

상자 상태(모래·물·구슬 위치, 생물 위치)는 앱을 나가도 저장되어 다음에 그대로 이어집니다.

## 배경화면으로 쓰기

메뉴의 **배경화면으로 설정**을 누르면 같은 상자가 라이브 배경화면이 됩니다. 홈 화면 뒤에서 기울임·흔들기·어둠에 반응하고,
터치는 런처가 쓰므로 받지 않습니다. 배경화면에서는 소리와 진동이 기본으로 꺼져 있고 메뉴에서 켤 수 있습니다.
앱과 배경화면은 저장 파일을 공유해 같은 상자를 보여 주며, 배경화면은 보일 때만 초당 30프레임으로 돌고 가려지면 멈춥니다.

## 설치하고 시작하기

1. APK를 설치하고 앱을 엽니다. ("출처를 알 수 없는 앱" 허용 필요) 권한은 진동만 쓰고, 묻지 않습니다.
2. 폰을 평평하게 놓고 기울여 보세요. 소리가 거슬리면 두 손가락으로 톡 쳐서 끕니다.
3. 배경화면으로 두려면 두 손가락으로 톡 → **배경화면으로 설정** → 시스템 미리보기에서 적용.

## 빌드하기

필요한 것: JDK 17 이상, `curl`, `unzip`. Android SDK는 아래 스크립트가 설치합니다.

```bash
# 1. Android SDK 설치 (기본 위치 /opt/android-sdk, 다시 실행해도 안전)
bash scripts/setup-android-sdk.sh

# 2. 디버그 APK 빌드
./gradlew assembleDebug
# → app/build/outputs/apk/debug/app-debug.apk

# 3. 단위 테스트와 lint
./gradlew testDebugUnitTest lintDebug
```

SDK를 다른 곳에 설치하려면 `ANDROID_HOME=/원하는/경로 bash scripts/setup-android-sdk.sh`처럼 실행하세요.
스크립트는 Gradle이 SDK를 찾을 수 있도록 `local.properties`(git 추적 제외)도 만들어 줍니다.
Android Studio를 쓴다면 이 폴더를 그대로 열면 됩니다.

디버그 APK는 저장소에 들어 있는 `app/debug.keystore`로 서명됩니다. 어느 컴퓨터(또는 CI)에서 빌드하든
서명이 같아서 이미 설치된 앱 위에 덮어 설치됩니다. 스토어 배포용 키는 아닙니다.

push마다 GitHub Actions가 디버그 APK를 빌드해 **Actions → Android CI → Artifacts → `app-debug`**에 올립니다.

## 동작 원리

- `world/Particles.kt` — 모래·물·구슬·말린 공벌레를 한 솔버로: 종류별 중력·감쇠로 적분 → 벽(반발, 구슬 충돌 이벤트) → 손가락·식물 밑동 밀기 → 공간 해시로 겹친 쌍 밀어내기(질량 가중, 물은 서로 끌어당김, 구슬끼리는 충돌 임펄스) → 실제 움직인 거리로 속도 갱신, 모래는 평평하면 정지.
- `world/Creatures.kt` — 공벌레(걷기·멈춤·말림, 말리면 솔버의 공 입자가 됨), 달팽이(자국 링버퍼), 딱정벌레(돌진·멈춤), 반딧불이(점멸·표류). 벽과 식물 밑동을 피하고 손가락에서 도망칩니다.
- `world/Terrarium.kt` — 상자 전체: 생성(시드), 한 스텝(1/60초), 이벤트 목록, 터치·흔들기 API, 저장/복원.
- `world/Plants.kt` — 식물 배치와 성장. `audio/Synth.kt` — 모든 소리를 수식으로 합성해 WAV로 만듭니다(음원 파일 없음).
- `render/TerrariumRenderer.kt` — 저해상도 비트맵(가로 ≈ 360px)에 픽셀 단위로 그리고 `TerrariumView`가 필터 없이 확대합니다.
- `TerrariumSession.kt` — 세계 + 렌더러 + 고정 스텝 시계 + 밤 계산 + 이벤트 → `SoundBank`(SoundPool) · `Haptics`(진동). 느린 폰이면 솔버 반복을 줄입니다. 뷰와 배경화면이 함께 씁니다.
- `TerrariumView.kt` — 앱 화면: 프레임 루프와 터치 해석(탭·롱프레스·드래그·두 손가락). `TerrariumWallpaper.kt` — 라이브 배경화면 엔진: 보일 때만 30fps, 터치 없음, 센서만.
- `Sensors.kt` — 가속도(저역통과 → 기울기, 고역통과 → 흔들기, 화면 회전 보정)와 조도. `Storage.kt` — 설정과 상자 저장(크기별 파일). `MainActivity.kt` — 전체 화면(시스템 바 숨김, 컷아웃까지), 센서 연결, Compose 메뉴.

순수 Kotlin 부분(세계·생물·식물·합성)에는 JVM 단위 테스트가 있습니다(`app/src/test`). 이 저장소의 CI는 기기 없이 빌드·테스트·lint만 합니다.

# 두 번째 앱 — 픽셀 샌드박스 (`sandbox/`, `com.llgl.sandbox`)

낙하 모래 게임(파우더 게임)식 샌드박스입니다. 화면이 셀 격자(가로 약 200칸)이고, 붓으로 재료를 뿌리거나 쌓아서 반응을 구경합니다.
테라리움과 별도 앱이라 둘 다 설치됩니다. CI 아티팩트 `sandbox-debug`, 로컬 빌드는 `./gradlew :sandbox:assembleDebug`.

| 분류 | 재료 | 하는 일 |
|---|---|---|
| 가루 | 모래, 화약 | 떨어져 쌓이고 액체 속으로 가라앉음. 화약은 불이 붙으면 폭발 |
| 액체 | 물, 기름, 산, 용암 | 물은 퍼지고 **전기가 통함**, 기름은 물 위에 뜨고 탐, 산은 벽·유리 빼고 녹임, 용암은 물을 만나면 돌+증기, 모래를 유리로 |
| 고체 | 벽, 나무, 식물, 유리 | 나무는 천천히 탐, 식물은 물을 먹고 자람, 유리는 안 녹음 |
| 기체 | 불, 연기, 증기 | 불은 탈 것에 붙어 있으면서 옆 재료에 옮겨 붙고, 탈 게 없으면 위로 떠올라 꺼지며, 물에 닿으면 증기로. 증기는 벽에 닿거나 식으면 다시 물 |
| 전기 | 전선, 배터리, 스위치, 전구, 전열선 | 배터리가 10틱마다 전류 펄스를 내보내고, 펄스는 전선을 **한 칸씩** 달린 뒤 그 칸이 잠시 쉬어 파도처럼 흐릅니다. 스위치는 토글 도구로 켜고 끄고, 전구는 전류가 오면 켜지고, 전열선은 전류가 오면 옆의 물을 끓이고 불을 붙입니다. 전선 고리에 번개를 한 번 치면 펄스가 양쪽으로 달려 반대편에서 만나 사라지고, 배터리를 붙이면 계속 돕니다 |
| 도구 | 지우개, ⚡ 번개, 스위치 토글 | 번개는 닿은 전선에 전류를 넣고 빈 칸에는 아크를 그리며 불을 붙입니다 |

조작: 붓 굵기 1~12, 가루·액체·기체는 빈 칸에만 뿌려지고 고체는 덮어 씁니다. 멈춤/한 틱/2× 속도/비우기. 격자는 앱을 나가면 저장됩니다.
핵심은 순수 Kotlin `sim/Grid.kt`(셀룰러 오토마타 + 전기 패스)와 `sim/Elements.kt`(재료 속성표)이고, `sim/GridTest.kt`에 모래·물·기름·불·용암·전기 회로·산·화약·식물·증기·저장 테스트가 있습니다.

# 세 번째 앱 — AI 게임 공방 (`gameforge/`, `com.llgl.gameforge`)

아이디어를 한 줄 적으면 **폰 안에서 돌아가는 Gemma**가 HTML5 게임 코드를 짜고, 앱이 바로 실행해 줍니다.
서버도 API 키도 없습니다. 모델 파일을 한 번 받은 뒤로는 비행기 모드에서도 됩니다. CI 아티팩트 `gameforge-debug`, 로컬 빌드는 `./gradlew :gameforge:assembleDebug`.

모델이 페이지를 바닥부터 짜지 않습니다. **엔진 템플릿**(캔버스, 프레임 루프, 터치, 시작 화면, 점수, 게임오버, 오류 표시)이 페이지를 맡고,
모델은 `CONFIG`와 `reset / update / draw / onTap / onDrag / onSwipe …` 같은 **게임 함수만** 씁니다. 고칠 때도 바뀌는 함수만 내고 하네스가 이름으로 병합합니다.

## 흐름

1. **모델 받기** — 오른쪽 위 ‘모델 받기’. 추천 모델 넷 중 하나를 고르면 시스템 다운로드 관리자로 받고, 받은 파일의 SHA-256을 Google 공식 파일의 값과 대조해 같을 때만 설치로 칩니다.
   폰에 이미 있는 `.task` 파일을 가져오거나 임의 주소로 받을 수도 있습니다.
2. **만들기** — 아이디어를 쓰거나 추천 칩을 누르고 ✨ 만들기. 모델이 게임 함수를 쓰는 모습이 실시간으로 보이고(토큰 수·속도·컨텍스트 사용량), 끝나면 엔진에 끼워져 바로 열립니다.
3. **플레이** — 전체 화면 WebView. 위 바에서 다시 시작, 오류 보기(→ **AI에게 고쳐 달라고 하기**), **수정 요청**(“공을 더 빠르게”), 메뉴에서 **코드 직접 편집**, 코드 보기, HTML 파일 공유, 이전 버전으로 되돌리기, 삭제.
   엔진이 게임 코드의 문법 오류나 함수 안의 예외를 잡아 화면 아래 빨간 띠로 보여 주고(한 번만), 게임 스크립트가 깨져도 엔진은 살아 있습니다.
4. **코드 편집기** — 게임 스크립트를 폰에서 바로 고칩니다. 함수로 점프, 엔진 API 안내, 저장·실행(새 버전으로 기록).
5. **보관함** — 만든 게임은 모두 저장되고(버전 기록 5개까지), 다시 열면 이어서 놉니다.

## 하네스가 모델과 일하는 법

- **새 게임**: 엔진 API 요약 + 규칙 + 아이디어 → 모델은 최상위 선언(`const CONFIG`, 변수, 훅 함수)만 ```js 블록으로 냅니다. 컨텍스트 2k면 80줄, 4k면 150줄 예산.
- **수정·오류 수정**: 하네스가 게임 스크립트를 **선언 단위**(`function`, `class`, `const/let/var`, 느슨한 코드)로 쪼개고, 컨텍스트에 맞게 보여 줄 부분을 고릅니다.
  다 들어가면 전부, 아니면 오류가 난 함수·`READ`로 요청된 것·상태 변수·`reset`·요청에 언급된 이름이 든 함수·`update`·`draw` 순으로 채우고 나머지는 한 줄짜리 **맵**(`- function spawn(dt)  (12줄)`)으로 보여 줍니다.
  모델은 바꿀 선언만 통째로 내고(`// DELETE 이름`으로 삭제), 안 보이는 함수가 필요하면 `READ 이름`이라고만 답해 한 번 더 받습니다(최대 3라운드).
- **병합**: 같은 이름은 자리에서 교체, 새 이름은 뒤에 추가, 엔진 이름(`rand`, `W` 등)을 `const`로 다시 선언하면 대입문으로 바꿔 SyntaxError를 막습니다. `let a = 0, b = 0;`은 두 선언으로 나눠 각각 바꿀 수 있게 합니다.
- **오류 매핑**: WebView 콘솔의 줄 번호(HTML 기준)를 셸의 자리표시 줄로 빼서 게임 스크립트 줄로 바꾸고, 그 줄이 든 함수를 보여 줍니다. 엔진이 잡은 `[게임 오류] update(): …`는 함수 이름으로 찾습니다.
- **저장 형식**: 게임마다 `shell.html`(엔진 + `/*__GAME__*/` 자리표시), `game.js`(모델·사용자가 고치는 부분), 둘을 합친 `index.html`, `meta.properties`, `history/*.js`. 옛 전체 HTML 게임은 처음 열 때 가장 큰 `<script>`를 떼어 같은 형식으로 바꿉니다.

엔진 템플릿은 `gameforge/src/main/resources/gameforge/shell.html`이고, `node gameforge/tools/engine-smoke.mjs`(Playwright + Chromium)가 샘플 게임으로 시작→플레이→게임오버→재시작, 스와이프, 문법 오류 격리, 훅 예외 1회 보고를 확인합니다.

| Gemma 3 1B q4 (4k) | 0.7 GB | 4096 | Hugging Face 토큰 | 가볍고 빠름 |
| Gemma 3 1B q4 (2k) | 0.6 GB | 2048 | 계정 없이 (해시 검증) | 가장 빠름. 짧은 게임만, 수정 요청은 대부분 안 됨 |

Google의 공식 Gemma 파일은 Hugging Face에서 약관에 동의한 계정만 받을 수 있어, 토큰이 있으면 네 모델 모두 공식 저장소에서 받습니다(앱이 토큰으로 서명된 CDN 주소를 먼저 얻고, 다운로드 관리자에는 토큰을 넘기지 않습니다).
실행 옵션: CPU/GPU 가속, 창의성(온도, 기본 0.6), Gemma 대화 템플릿 직접 적용(모델이 설명만 늘어놓을 때).

## 동작 원리

- `llm/Engine.kt` — MediaPipe LLM Inference(`tasks-genai` 0.10.35) 래퍼. 전용 스레드 하나가 모델을 들고 불러오기·스트리밍 생성·취소·해제를 직렬로 처리합니다. 메모리 압박 알림이 오면 쉬고 있을 때 모델을 내립니다.

- `harness/CodeMerge.kt` — 이름으로 교체·추가·삭제, 엔진 이름 충돌 처리, 변경 요약(“update, draw 수정 · spawn 추가”). `harness/ContextBuilder.kt` — 예산 안에서 보여 줄 선언 고르기와 맵. `harness/Shell.kt` — 엔진 템플릿, 조립, 줄 번호 매핑, 옛 게임 분리, 모델용/사용자용 API 요약.
- `gen/Prompts.kt` — 생성·수정·오류 수정 프롬프트. `gen/GenerationController.kt` — 모델 불러오기 → 컨텍스트 선택 → 토큰 수 확인(400토큰 이상 남아야 시작, 모자라면 보여 줄 양을 반으로) → 스트리밍(80ms마다 UI 갱신) → 파싱·`READ` 라운드 → 병합 → 저장.
- `model/` — 모델 목록(`ModelCatalog`, 공식 SHA-256 포함), 파일 폴더·가져오기(`ModelFiles`), 시스템 DownloadManager 기반 내려받기 + 토큰 리디렉션 해석 + 해시 검증(`Downloader`).
- `games/GameStore.kt` — 게임별 폴더(`shell.html`, `game.js`, `index.html`, `meta.properties`, `history/*.js`), 옛 형식 자동 분리.

순수 Kotlin 부분(하네스 전부·프롬프트·모델 목록·저장소)에 JVM 테스트가 있습니다(`gameforge/src/test`). 기기 없이 빌드·테스트·lint만 하는 CI라, 실제 생성 속도와 품질은 폰에서 확인해야 합니다.

# 네 번째 앱 — 진동 뮤직 (`vibe/`, `com.llgl.vibe`)

다른 앱이 내는 소리를 **그 자리에서 진동으로** 바꾸는 앱입니다. YouTube·브라우저·음악 앱에서 재생하면 그 소리를 받아 비트·저음·음높이를 뽑아 모터를 떨게 합니다.
소리는 끄고 진동만 느낄 수 있습니다. Android 10 이상. CI 아티팩트 `vibe-debug`, 로컬 빌드는 `./gradlew :vibe:assembleDebug`.

## 쓰는 법

1. **▶ 시작** — 오디오 캡처 권한(마이크 권한으로 표시됨), 알림 권한(Android 13+), 그리고 **화면 캡처 동의** 창이 차례로 뜹니다. 소리만 받고 화면은 저장하지 않습니다.
2. 다른 앱으로 가서 재생합니다. 포그라운드 서비스라 다른 앱이 떠 있어도 계속 진동하고, 알림에서 소리 켜기/끄기와 정지를 할 수 있습니다.
3. **진동 방식**은 다섯 중 하나:
   - **리듬**: 비트마다 한 번씩 툭(센 비트는 길고 세게)
   - **베이스**: 저음(150 Hz 아래) 크기를 따라 웅웅
   - **멜로디**: 음높이를 따라. Android 16 + 주파수 제어 모터(Pixel 등)면 음높이를 모터 주파수로 옮겨 **실제로 음을 냅니다**. 아니면 음이 높을수록 빠르게 톡톡거립니다.
   - **목소리**: 말소리(300–3000 Hz)의 음절 하나하나를 또박또박. 자음이 시작될 때 세게 치고 음절 사이에서는 바로 놓아, 영상·팟캐스트·게임 대사가 리듬으로 느껴집니다.
   - **전부**: 리듬 + 베이스 + 목소리
   진동 세기는 늘 **소리 세기에 비례**합니다(큰 소리는 세게, 작은 소리는 약하게, 아주 작은 소리는 없음). 세기 슬라이더는 그 위에 곱해집니다.
4. **배경 소리 빼기**(기본 켬): 1~2초 넘게 그대로 이어지는 웅웅·쉬익·드론·팬 소리는 배경으로 보고 빼며, 말소리·비트·음처럼 왔다 가는 소리만 진동으로 냅니다. 노래가 아닌 영상·게임에서 계속 웅웅거리지 않게 하는 스위치입니다.
   **세기** 슬라이더(놓으면 미리 느껴 봅니다), **소리 끄기** 스위치(기본 켬: 미디어 볼륨 0, 정지하면 원래대로). 방식·세기·소리 끄기·배경 빼기는 기억됩니다. 진동이 약하면 시스템 설정 › 소리 및 진동 › **미디어 진동**을 올리세요.
5. 화면의 원이 음량(안쪽)과 저음(바깥 후광)으로 숨 쉬고 비트마다 테두리가 번쩍입니다. 3초 넘게 소리가 안 들어오면 알려 줍니다. DRM이 걸린 앱(Spotify, Netflix 등)은 시스템이 캡처를 막아 소리가 들어오지 않습니다.

## 동작 원리

- `capture/CaptureService.kt` — `mediaProjection` 포그라운드 서비스. `startForeground` 뒤에 동의 토큰으로 `MediaProjection`을 얻고(Android 14+ 순서 요구), `AudioPlaybackCapture`(미디어·게임 용도의 재생)를 `AudioRecord` 16 kHz 모노로 받아 전용 스레드가 20 ms 블록마다 분석, 100 ms 창 단위로 모터에 보냅니다. 소리 끄기는 미디어 볼륨을 0으로(캡처는 볼륨 적용 전의 각 앱 스트림을 받으므로 그대로 들립니다), 정지·종료 시 복원.
- `analysis/LiveAnalyzer.kt` — 스트리밍 분석. 20 ms 블록마다 전체·저역(150 Hz 이하, 100 ms 이동 평균)·말소리 대역(300–3000 Hz)·고역(2.5 kHz 이상) 에너지를 잽니다. **배경 빼기**: 대역마다 최근 낮은 값에 붙어 있다가 블록당 3 %씩 천천히 올라오는 바닥(noise floor)을 두고, 그 바닥의 2~2.5배를 뺀 나머지만 전경으로 칩니다. 그대로 이어지는 소리는 1.5초쯤이면 바닥에 잠겨 0이 되고, 말소리의 쉼이나 비트 사이의 빈틈은 바닥을 바로 끌어내립니다. 전경 에너지를 **절대 음량**으로 환산해 음량·베이스·목소리를 냅니다(진폭의 0.6제곱, RMS 0.35(−9 dBFS)에서 최대, −50 dBFS 아래는 0 — 소리가 작으면 진동도 작습니다). 온셋은 두 블록 평균 전경 에너지의 로그 증가량을 세 대역 가중합해 최근 최대 온셋(2초 반감, 하한 3.0)으로 나눈 0–1. 비트는 다음 블록이 더 크지 않은지 확인한 뒤 한 블록(20 ms) 늦게 확정(지역 최대, 최근 평균의 1.4배 초과, 120 ms 간격). 음높이는 8 kHz 링 버퍼의 64 ms 창에 축약 YIN(`analysis/Pitch.kt`).
- `haptics/LiveScore.kt` — 프레임이 하나씩 올 때의 악보: 비트 펄스(세기에 따라 40–120 ms 감쇠), 베이스 유지/감쇠, 목소리(즉시 올라가고 오르는 양만큼 더 세게 쳐서 자음 끝을 살리고, 세 프레임 안에 놓음), 음높이에 따른 멜로디 틱 상태를 들고 있으며, 한 창의 세기 배열을 `createWaveform` 구간으로, 주파수 제어 모터에서는 포락선 제어점(옥타브 접기, 제어점 길이·수 한계 준수)으로 만듭니다. `haptics/Score.kt`에 공통 함수(펄스 속도, 세기 스케일, 옥타브 접기).
- `haptics/VibeEngine.kt` — 모터 능력 감지(진폭 제어, Android 16 주파수 포락선·주파수 범위·제어점 한계·공진 주파수)와 창 단위 발행. API 26 미만은 켜고 끄기 패턴으로 대체.
- `analysis/Dsp.kt` — RBJ 바이쿼드 필터(저역·고역·대역), RMS. `capture/LiveState.kt` — 서비스와 화면이 공유하는 상태(`StateFlow`). `Prefs.kt` — 방식·세기·소리 끄기.

순수 Kotlin 부분(필터·음높이·스트리밍 분석·악보)에 JVM 테스트가 있고, 합성 신호(클릭 열, 60 Hz 저음, 1 kHz 음절 열, 백색 잡음, 220 Hz 사인)로 미래를 보지 않고도 비트가 클릭 60 ms 안에 드는 것, 이어지는 저음이 처음엔 느껴지다 2초 뒤 배경으로 잠기는 것, 음절은 저음 위에서도 전경에 남고 음절 사이는 비는 것, 그대로 이어지는 잡음은 사라지고 비트를 만들지 않는 것, 음높이 검출을 확인합니다. 매니페스트 테스트는 `VibeApp`·서비스 선언과 권한 목록을 지킵니다. 실제 모터의 느낌과 캡처 동작은 폰에서 확인해야 합니다.

# 다섯 번째 앱 — 하늘 거북이 (`turtles/`, `com.llgl.turtles`)

**잠금화면용 라이브 배경화면**입니다. 바다거북들이 하늘을 헤엄치듯 날아다닙니다. 시간에 따라 하늘빛이 바뀌고(밤엔 별과 초승달), 구름이 흐르고, 폰을 기울이면 깊이에 따라 층이 다르게 흐르고, 톡 치면 가까운 거북이가 한 바퀴 구르며 반짝이를 뿌립니다.
CI 아티팩트 `turtles-debug`, 로컬 빌드는 `./gradlew :turtles:assembleDebug`.

## 쓰는 법

1. 앱을 열면 미리보기가 돌고 있습니다. **배경화면으로 설정**을 누르면 시스템 라이브 배경화면 미리보기가 열립니다.
2. **Android 14 이상**: 미리보기의 ‘배경화면 설정’에서 **잠금화면**(또는 홈·잠금 모두)을 고르세요. 잠금화면에 놓이면 시스템이 알려 주므로 거북이들이 **시계 아래(위쪽 40% 바깥)**로만 다닙니다. Android 13 이하는 잠금화면에 라이브 배경화면을 둘 수 없어 홈 화면에만 됩니다.
3. 설정: 거북이 수(1~14), 속도(50~200%), 기울임 시차 켜고 끄기, ‘잠금화면처럼 미리보기’(시계 자리를 비워 둔 모습 확인). 설정은 바로 배경화면에 반영됩니다.

## 동작 원리

- `sky/SkyScene.kt` — 순수 Kotlin 장면. 거북이마다 깊이(0.45~1: 멀수록 작고 느림), 차선(baseY), 방향, 속도, 지느러미 위상이 있고, 바다거북처럼 **저었다가 미끄러지는** 리듬으로 나아갑니다(지느러미를 저을 때 빨라짐). 위아래로 살랑이고, 12~30초마다 한 번 **몸을 돌려** 반대로 가며(1.3초, 가운데서 옆모습), 화면 밖으로 나가면 반대쪽에서 새 차선·새 깊이로 들어옵니다. 잠금화면 레이아웃이면 차선 상한이 40%로 내려가고, 위에 있던 거북이는 순간이동 대신 천천히 내려옵니다. 탭은 가장 가까운 거북이에게 0.9초 배럴 롤과 반짝이 14개. 구름 7개는 깊이별 속도로 흐르고, 별 70개는 고정.
- `sky/Palette.kt` — 시각별 하늘 키프레임(자정·새벽·아침·낮·저녁·밤)을 선형 보간: 위·아래 그라데이션 색, 별 밝기, 밤 정도.
- `render/SkyRenderer.kt` — 그라데이션 하늘 → 별(깜빡임)·초승달 → 먼 구름 → 깊이순 거북이(지느러미 네 개는 둥근 막대를 위상에 따라 회전, 등딱지 테두리·본체·비늘 일곱, 머리·눈·꼬리; 배럴 롤은 세로 스케일을 cos으로 뒤집고 뒤집힌 동안 배 색) → 가까운 구름 → 반짝이. 기울임 시차는 깊이에 비례한 오프셋, 런처의 줌아웃은 전체를 살짝 축소.
- `TurtleWallpaper.kt` — `WallpaperService`. 보일 때만 30fps, 터치 허용(탭 = 롤), 1분마다 시계를 다시 읽어 하늘빛, Android 14+의 `wallpaperFlags`/`onWallpaperFlagsChanged`로 잠금화면 여부, `onZoomChanged`, 설정 변경 즉시 반영, 가속도계는 설정이 켜졌고 보일 때만.
- `TurtleView.kt`·`MainActivity.kt` — 같은 장면의 앱 내 미리보기(Compose `AndroidView`)와 설정, `ACTION_CHANGE_LIVE_WALLPAPER`로 시스템 미리보기 열기.

장면 로직에 JVM 테스트가 있습니다: 1분 동안 거북이가 계속 움직이고 가장자리에서 되돌아오며 차선 안에 있는지, 탭이 가장 가까운 거북이를 굴리고 반짝이를 뿌린 뒤 끝나는지, 잠금 레이아웃이 시계 아래로 유지하고 전환 시 부드럽게 내려오는지, 구름이 흐르고 되돌아오는지, 속도 설정이 이동 거리에 비례하는지, 마릿수 한계, 크기 변경 시 비례 유지, 팔레트가 하루 내내 매끄럽고 자정에서 이어지는지.
